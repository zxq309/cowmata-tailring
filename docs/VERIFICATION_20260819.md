## What was actually executed and passed

- `tests/test_contracts.py` — **36 / 36 passed**, real execution.
- `tests/test_pipelines.py` — **12 / 12 passed**, real execution. This builds a 4-cow /
  8-session synthetic corpus and runs the whole batch chain end to end: cache →
  feature table (9,696 rows × 120 v2 columns) → GBDT bundle (8 task models fitted with
  the sklearn backend) → prediction → review queue.
- `cowmata check-data --root .` — PASS; 1,199 annotations, 132 sessions, 0 problems,
  2 warnings (deprecated `TAIL_WAGGING` present; 132 caches absent locally).
- `cowmata plan-storage --cows 200 --days 7` — 292.9 GB (schema 1) → 101.4 GB (schema 2).
- Feature parity: `FEATURE_VERSION=1` produces exactly the 104 feature names, **in the
  same order**, that are stored inside `weights/deploy/gbdt_full.joblib`. Verified by
  reading the pickle byte stream, not by assumption.
- Demo session `demo_session_60s` (schema 1, 2,999 frames) → **120 dense 2 Hz points**,
  matching the 20260818 documented behaviour.
- Synthetic dataset generator writes a schema-2 cache and reads back at 0.999 g mean
  acceleration magnitude.
- Amplitude self-calibration: a simulated ring at mid-tail (lever arm ×3) produced a
  gyroscope feature ratio of ×3 before calibration and within 15% of ×1 after.
- Hysteresis assembly: an event with a 1 s probability dip is scored as **2 intervals**
  under the 20260818 single-threshold rule and **1 interval** under hysteresis.
- Bundle round-trip: `train_gbdt` wrote per-event thresholds and `feature_version=2`;
  `COWMATA.predict` read them back and used them unchanged, falling back to 0.5 only
  for `MOUNTING`, which had no positives to fit.
- `cowmata check-env` runs to completion **on a host with no torch**, reporting which
  subcommands remain available. It previously raised `ModuleNotFoundError`.
- `cowmata diagnose --root .` — wrote the annotation audit over the real 1,199-row
  label table; per-cow concentration reports `unavailable: sample table not found`,
  which is correct, because `samples.csv` is not in the repository.

## Known limitations carried forward from 20260818

- `review_coverage` is still empty. **Event precision and false alarms per cow per 24 h
  remain not claimable.** The metric code now says so in the report rather than
  printing an over-optimistic number.
- Cow imbalance is unchanged in the existing data: 2 of 6 animals hold ~96% of
  supervised samples. Any pooled cross-cow figure computed on it has no statistical
  power. This is the reason for the grouped-k-fold and bootstrap machinery, which only
  pays off once the 200-cow collection lands.
- `MOUNTING` / `MOUNTED_BY` have **zero** annotated intervals so far. They exist in the
  taxonomy, the model and the metric suite, and they will report `not_evaluable` until
  the annotation tool starts emitting them.
- The deployed GBDT bundle carries no `thresholds` or `feature_version` key, because it
  predates them. It therefore runs at `feature_version=1` with 0.5 thresholds, exactly
  as before. The next `train_gbdt` run writes both.
- The GBDT chain was exercised with the **sklearn** booster backend, because xgboost is
  not installed here. The xgboost path is the production default and is unchanged from
  20260818; it is code-identical in `gbdt.py` and untested in this container.
- The synthetic corpus proves the plumbing, not the physiology. Every accuracy figure it
  produces is meaningless as a performance claim — the signal was generated by the same
  assumptions the features encode.
