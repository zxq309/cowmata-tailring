# 20260819 migration record

## Structure

Three top-level Python concepts became one.

| 20260818 | 20260819 |
|---|---|
| `cattle_imu/` (13 modules) | `cowmata/` (15 modules) |
| `cowmata/` (API + CLI wrapper) | merged into `cowmata/` |
| `scripts/` (12 argparse programs) | 6 four-line shims over `cowmata.cli` |

- `windowing.py` is gone. Dense training does not build per-label windows, so the
  window-bounds contract it protected no longer exists.
- `amp.py` + `load_control.py` → `runtime.py`.
- `state_machine.py` → `postprocess.py`, joined by the new interval assembly.
- `annotations.py` → `labels.py` (taxonomy) + loader helpers.
- `model.py` → `models.py`, rewritten as MS-TCN++ with a boundary head.
- `fusion.py` → `experiments/fusion.py`. The 20260818 report concluded fusion did
  not beat the better single branch; it is kept as evidence, not as a dependency.
- `train_event_loco.py` and `predict_continuous.py` are removed. The first was an
  unadopted branch, the second overlapped `inference.py` and required a causal
  checkpoint that does not formally exist.

## Compatibility

`cowmata/compat.py` aliases `cattle_imu.*` to `cowmata.*` in `sys.modules`, lazily,
so `weights/deploy/gbdt_full.joblib` still unpickles without keeping a second
package alive. The bundle is not rewritten: it is byte-identical to the artefact
whose predictions were verified, and rewriting it would spend that verification.

`features.FEATURE_VERSION` guards the numerical contract. Version 1 reproduces the
deployed 104-column feature list **by name and in order** (asserted in
`tests/test_contracts.py` against the bytes of the deployed bundle). Version 2 adds
amplitude self-calibration and two rotation invariants, which changes the values of
the shared gyroscope columns, so a bundle with no recorded version is treated as
version 1.

## Data contract

- Cache stores int16 counts, not float32 physical values (calibration applied on read).
- The three magnitude channels are dropped; they are recomputable in microseconds.
- The timing-quality flag is stored as sparse intervals.
- Timestamps are no longer stored; within a segment they are a closed-form expression.
- New per-session metadata: `tail_position` (`root` / `mid` / `tip` / `unknown`).

Net effect: 52 → 18 bytes per 50 Hz frame. For the planned 200 cows × 7 days that is
293 GB → 101 GB.

## Labels

- Added `MOUNTING` and `MOUNTED_BY`.
- `TAIL_WAGGING` moved to `DEPRECATED_EVENT_CODES`: 4 intervals from 1 animal. It is
  still read without error, so the historical table stays loadable, but it is not a
  training target and not a reported metric.
- `FEEDING` stays readable and stays folded into `UPRIGHT`. A tail ring cannot
  separate feeding from standing. The 188 existing intervals are not deleted: if a
  neck collar or ear tag is added later they are immediately usable.

## SSL cache

Not restored. It was generated by a code path that had the cross-segment
contamination defect, it is derived data that can be rebuilt at any time, and the
right move at the next data scale is to fine-tune published wearable-SSL weights
rather than to retrain a VICReg branch on 131 hours.
